## The mechanism, decided

Commitment comes from the state the cast runs in, not from a flag planted on an existing one.
Every flag-based attempt failed (ticket 33, three times), and neither reference implementation
uses one: Enemy Magelock's only `BSIsActiveModifier` binds `bAllowRotation`, and measurement on
ticket 54 showed `bAnimationDriven` never rises on the MSCO fire-and-forget cast the owner
certifies as the correct root.

**What Magelock does, and what we borrow:** it replaces the *generators* behind the vanilla
nodes where casting meets locomotion — `MagicCastingLocomotionState` (`#0926`),
`MagicCast_Standing` (`#0930`), `MagicCast_TurnLeft_State`, `MagicCast_TurnRight_State` — so
casting stops routing through a locomotion-blending state and there is nothing left to
translate the actor. Rotation is handled separately by a `BSIsActiveModifier` binding
`bAllowRotation`. Its clips are vanilla; the DAR `_CustomConditions\94010` folder is a
file-override carrier, not new animation.

**Where ours differs: it applies globally.** Magelock carries a two-state machine
(`#altmag$174 BNPCBehavior` → `NPCMagicBehavior` / `PlayerMagicBehavior`) whose `startStateId`
binds to a graph variable, purely to treat the player differently. We do not want that split —
the standing rule is everything roots, every actor, movement out of scope — so that machinery,
and the open question about which variable index 4 names, is dropped rather than reproduced.
Likewise no per-cast-type discrimination: SBF's `iSBF_LeftCastType` / `iSBF_RightCastType` are
available and already installed (mod code `sbeef`), but nothing in the requirement needs them.
Noted here so a later requirement can pick them up without rediscovering them.

## Build steps

1. **Contention read first.** The nodes above sit in territory `msco`, `pscd`, `sbeef`, and
   `shtb` already patch, and Nemesis resolves single-value conflicts last-checked-wins — this
   bit us on ticket 33, where `shcc` silently displaced `sbeef` and `pscd` edits. Produce the
   table of every node we intend to touch against every mod code that touches it, and decide
   each displacement deliberately before authoring. `sbeef` is both a thing not to break and a
   framework already relied on elsewhere.
2. **Retire `shcc`.** It is the failed flag-plant patch (`nemesis/Nemesis_Engine/mod/shcc/`,
   generator `.scratch/shcc-build/build_shcc.py`), deployed inert. The new patch replaces it;
   do not layer on top of it.
3. **Author the patch** under its own mod code, generated by a script in the repo the way
   `shcc` was — the file set is regenerable, not hand-maintained.
4. **One state first.** Prove a single cast path roots before building the matrix (ticket 33's
   lesson, learned three times). Nemesis needs Update Engine before Launch whenever the file
   set changes.
5. **Owner feel test** on the prototype, then the rest of the matrix.
